# Release Notes - v0.2.0

**Release Date:** February 14, 2026

## 🎉 New Features

### Custom Subject Schema Support

- Added `subject` parameter to `ClientProps` allowing custom token verification schemas
- Enables server-side validation of incoming tokens against custom claim structures
- Falls back to default OpenAuthster subject schema if not provided
- Example:

  ```typescript
  const mySubjectSchema = createSubjects({
    user: v.object({
      id: v.string(),
      email: v.string(),
      role: v.union([v.literal("admin"), v.literal("user")]),
    }),
  });

  const client = createOpenAuthsterClient({
    // ... other options
    subject: mySubjectSchema,
  });
  ```

### User Management (Admin Features)

Added comprehensive user management methods for server-side admin operations (requires `secret`):

- **`getUserById(user_id: string)`** - Fetch a specific user by their ID
- **`getUsers(filters?: GetUserListFilters)`** - Fetch paginated list of users with optional filtering
- **`updateUserById(user_id: string, data: UpdateUserByIdData)`** - Update user data by ID
- **`deleteUserById(user_id: string)`** - Delete a user by their ID

All methods include proper error handling and validation using Valibot schemas.

### Token Management

- **`getToken()`** - Retrieve the current access token or get it from localStorage
- **`setTokenToCookie()`** - Store the access token in a secure cookie (browser-side only)
  - Sets cookie with: `path=/; secure; samesite=strict;`
- **`verify(token?: string)`** - Verify token authenticity using the subject schema
  - Can verify the current client token or a specific token
  - Returns boolean indicating validity
  - Logs errors to console for debugging

### Enhanced Error Handling

- **`error` Property** - New public property containing OAuth error information
  - Type: `{ error: string; error_description: string | null } | null`
  - Populated when authorization callback returns an error
  - Available for checking auth flow failures
- **Error Parameter in Listeners** - Initialization listeners now receive an optional error parameter
  - Callback signature: `(client: OpenAuthsterClient, error?: ErrorType) => void`
  - Enables reactive error handling in UI components

### User Info Property

- **`userInfo` Property** - Contains user information returned by the OAuth provider
  - Type: Generic `UserInfo` (default: `{ provider: string }`)
  - Populated after successful authentication
  - Includes provider-specific data based on requested scopes

## 🔧 Improvements

### Enhanced Token Extraction

- `setTokenFromRequest()` now supports cookie-based token extraction as fallback
- Searches for `access_token` cookie if Authorization header is not present
- Improved server-side compatibility

### Better Token Verification

- `setTokenFromRequest()` now verifies token authenticity before accepting it
- Uses configured subject schema for validation
- Rejects invalid tokens with proper error logging
- Enhanced security for server-side operations

### Manual Callback Handling

- Exposed `callback()` method for manual OAuth callback processing
- Enables custom redirect flows and advanced use cases
- Automatically cleans up URL query parameters after exchange

### Public Method Documentation

- All public methods now include comprehensive JSDoc comments
- Clear indication of browser-only vs server-side methods
- Usage examples in documentation
- Parameter and return type descriptions

## 📝 API Changes

### Breaking Additions

All new features are paired with the new v0.2.0 issuer.

### New Optional Parameters

- `subject?: SubjectSchema` in `ClientProps` - Optional custom subject schema
- Error parameter in initialization listener callbacks - Optional, existing code continues to work

- Better error handling when tokens are missing or invalid

## 🚀 Migration Guide

### From v0.1.x to v0.2.0

Update issuer and WebUI to the v0.2.0 all together.

1. **Add custom subject validation** (optional):

   ```typescript
   import { createSubjects } from "@openauthjs/openauth/subject";

   const client = createOpenAuthsterClient({
     // ... existing options
     subject: myCustomSubjectSchema, // New optional parameter
   });
   ```

2. **Update initialization listeners** to handle errors (optional):

   ```typescript
   client.addInitializationListener("key", (client, error) => {
     if (error) {
       // Handle error
       return;
     }
     // Continue with normal flow
   });
   ```

3. **Use new user management features** (if you have admin needs):
   ```typescript
   const users = await client.getUsers({ page: 1, limit: 10 });
   const user = await client.getUserById("user_id");
   ```
