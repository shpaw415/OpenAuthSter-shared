# Release v1.0.0

## Overview

`v1.0.0` is the first major release of the OpenAuthster shared package and Web Client SDK since `v0.3.0`. This release focuses on preparing the SDK and shared contracts for multi-user administration, stricter ownership boundaries, richer role and invite support, and better typed client-side integrations.

## Breaking Changes

- No in-place upgrade path is supported for this release.
- Moving from `v0.3.0` to `v1.0.0` requires a clean install and a fresh integration pass.
- Database schemas, shared endpoint contracts, and client response types changed substantially in this release.

## Changes

### Multi-User and Ownership Schema Updates

- Updated shared database schemas to support multi-user and ownership-aware flows.
- Added `owner_group_id` support across the relevant tables and helper logic.
- Updated project-related types and schema fields to reflect the newer ownership model.
- Adjusted column naming and table structures to better support collaborative administration.

### Invites and Collaboration Contracts

- Added and refined invitation tables used by the WebUI collaboration flows.
- Expanded invite records with labels, inviter data, owner-group data, and invite-type fields.
- Updated shared endpoint and table contracts so invite workflows can be typed consistently across projects.

### Roles and User Management

- Added role support to the shared client and response contracts.
- Added `setRoleById` support and updated project data handling for role-aware administration.
- Made user and OTF-related schema fields more flexible, including nullable role and email support where required.
- Moved the delete-user logic into the shared package so user cleanup can be reused consistently.

### Client SDK Improvements

- Improved the high-level client request flow so expired access tokens can trigger refresh automatically during requests.
- Improved error handling across the client SDK.
- Added better provider type inference and richer typed responses in the client surface.
- Added email data to the relevant client endpoint responses.
- Improved metadata typing and documentation for client consumers.

### Provider and Auth Flow Updates

- Updated provider-related contracts, including required scope handling for OAuth providers.
- Added support for `authCodeType` and related custom send-code flows.
- Updated password and code template handling to work with distinct template IDs.
- Added shared support for newer WebUI project-builder and password UI copy flows.
- Continued QR and passkey-related fixes and type refinements.

### General Cleanup and Type Quality

- Removed unused or outdated types and endpoint definitions.
- Refined shared schema inference for `getUsers`, `getUserById`, and related response types.
- Updated package internals and dependencies to support the `1.0.0` contract surface.
- Applied Biome cleanup and broader type-quality improvements across the package.

## Upgrade Notes

- There is no supported incremental upgrade from `v0.3.0`. Install `v1.0.0` cleanly and re-validate your integration.
- If you consume shared database schemas directly, review project, invite, OTF, and user-related table definitions before deploying.
- If you use the high-level client SDK, re-check typed response handling for metadata, provider data, roles, and email fields.
- If you rely on admin or collaboration features, verify your role, invite, and ownership flows against the new shared contracts.
